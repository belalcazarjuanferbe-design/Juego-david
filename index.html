    Principios SOLID aplicados

    • S: cada clase hace una sola cosa (Game maneja el estado del juego; HUD pinta; Logger registra; RoundSplash anuncia la ronda; Stats cuenta; cada Rule evalúa una condición).
    • O: nuevas reglas, rondas o estados se añaden con clases nuevas, sin tocar Game.
    • L: cualquier Rule (simple, Not, Lag o AllOf) es intercambiable donde se espera una Rule.
    • I: interfaces pequeñas (Rule.ok, Observer.init, LevelFactory.create).
    • D: Game recibe por constructor las fábricas y el bus de eventos; depende de abstracciones, no de reglas concretas. Bajo acoplamiento: la UI solo se entera de cambios por eventos.

    Patrones: Factory Method (LevelFactory) · Decorator (Not, Lag) y Composite (AllOf) · Strategy (Rule) · Observer (EventBus) · State (GameState).
